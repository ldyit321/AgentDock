# AgentDock UI 与交互设计

版本：v1.1 评审稿｜日期：2026-10-28｜阶段：技术设计，未实施

配套 [UI 设计预览](AgentDock-UI设计预览-v1.1.html) 为自包含静态示意，可切换工作台、Skill 库和 MCP 连接。全部为虚构示例数据，不连接后端、不代表产品已实现。

## 1. 范围、依据与设计原则

本版替代 v1.0 中的前端建议；v1.0 文档和预览保留为历史，不作为当前框架选型。本文依据项目 `AGENTS.md`、需求与功能基线 v1.0、功能简版及会话接续说明，设计普通用户和管理员的网页界面。U 项沿用已确认需求；本文布局、字段组织、组件、文案和具体交互均为 D（建议默认值），需要评审后进入实施计划。协议、权限、恢复能力未经产品集成验证，本文不声称已有网页或功能。

系统与接口细节见配套 [技术设计](AgentDock-技术设计-v1.1.md)；有跨文档差异时应在评审中同步，不能由前端自行解释执行语义。

用户已确认模型为支持多模态的 OpenAI 兼容服务，图片和文档输入必须能被解析理解（U）。处理与上下文细节见 [多模态输入设计](AgentDock-多模态输入设计-v1.1.md) 和 [上下文与记忆设计](AgentDock-上下文与记忆设计-v1.1.md)。OpenAI-compatible 仅描述兼容接入约定，不代表所有模型原生接受 PDF 或所有文档格式；页面依据后端实际能力和解析结果显示，不承诺未经验证的原生格式支持。

界面首先服务于“提出任务—看清过程—必要时介入—检查结果—继续工作”。工作台不是固定脚本表单，也不以示例文件类型限制任务。允许零 Skill、零代码执行、零产物；简单任务可以不建立 Todo。用户不必理解 LangGraph、检查点或 Sandbox 参数才能完成普通工作。

用户已确认前端采用 Vue 3 + JavaScript、持久化采用 MongoDB（U）；Element Plus 作为采纳用户偏好的组件方案。其余工程细节为 D：Vue 3 Composition API、单文件组件的 <script setup>（不使用 lang="ts"）、Vite、Element Plus 2、Vue Router 4、TanStack Vue Query，原生 fetch 请求与 SSE 事件。Element Plus 提供表单、表格、弹窗、抽屉和键盘交互基础；通过少量 CSS 调整三栏布局、密度和状态层次，不另造设计系统。页面只组织输入和展示服务端事实，运行判定、权限和恢复规则留在业务层，便于后续替换网页或接入已有系统。MongoDB 仅由后端访问，浏览器不直连数据库，也不因数据库选型改变归属校验和 DTO 边界。

采用“中文工具工作台”方向：稳定的列表和连续的过程记录，突出当前需要人做的事。明确区分计划、执行证据、结果校验和环境清理；不展示模型内部推理，不用假百分比或动画暗示确定进度。

## 3. 视觉与布局规格

### 3.1 六色基础 tokens

| 名称 | 色值 | 用途 |
|---|---|---|
| 工作纸白 | `#F5F7FA` | 页面底色；内容面使用组件默认白色 |
| 墨蓝 | `#182B40` | 主文字、页面标题、重要结构 |
| 结构灰 | `#66788A` | 次要文字、分隔、非活动状态 |
| 港湾蓝 | `#175CD3` | 主按钮、链接、选中、键盘焦点 |
| 核验绿 | `#18794E` | 已验证、已完成、连接正常 |
| 处置红 | `#B42318` | 失败、危险操作、需处理异常 |

等待以港湾蓝浅底配“等待回答／等待批准”文字和图标表达，不新增第七种基础色。浅底和边框由以上色值透明度派生；实现时验证文字及焦点对比度，不能直接把淡色用于小字。状态始终同时包含文字或图标，避免只靠颜色辨别。默认仅浅色主题，深色主题不作为首版额外工作。

字体建议 `"Microsoft YaHei UI", "PingFang SC", system-ui, sans-serif`；代码和日志采用 `Consolas, monospace`。正文 14px／行高 22px，消息正文 15px／24px，辅助信息 12px／18px，分组标题 16px／24px，页标题 20px／28px。长文本靠左，消息正文最大宽度约 760px；不以超大营销标题占据工作区。

间距以 4px 为单位，常用 8／12／16／24px。按钮高建议 32px，触控模式至少 44px；表格默认中等密度，可折叠行内详情。面板边框承担分区，避免每个消息都做同等阴影卡片。普通圆角 6px，浮层 8px，阴影只用于浮层。最有识别度的元素是右侧“本轮任务台”：待处理人机交互在顶部，计划、执行和文件依次下排。

```text

| AgentDock          | 对话标题             历史 / 更多      | 本轮任务台        收起  |
| [+ 新建对话]       | 本轮：执行中       已用时 / [取消任务] | 等待你处理（如有）      |
| 搜索本人对话       +--------------------------------------+-------------------------+
| 今天               | 用户：任务正文与输入文件引用          | 计划 Todo               |
|   对话 A [执行中]  |                                      |  [进行中] 整理资料      |
|   对话 B [待回答]  | Agent：简短进度与操作摘要             |  [待处理] 检查结果      |
| 更早               |   工具调用摘要 [展开]                 +-------------------------+
|   对话 C           |                                      | 执行与验证 [查看详情]   |
|                    | 问题 / 审批卡（同右侧任务定位）       | Skill / MCP / 修复记录  |
|                    |                                      +-------------------------+
| Skill 库           +--------------------------------------+ 对话文件                |
| MCP 连接           | [输入任务或继续追问……]               | 输入 / 工作文件 / 产物  |
| 账户 / 管理        | 附件  Skill范围  修复设置   [发送]     | 文件名 版本 大小 [下载] |
+--------------------+--------------------------------------+-------------------------+
```

桌面宽度 ≥1280px：左栏 240px，右栏 320px，中栏弹性且不小于 520px；容器不足时优先收起右栏。1024–1279px：左栏 208px、右栏抽屉。768–1023px：左栏改抽屉，任务台以按钮展开。小于 768px：单栏消息，顶部“对话／任务／文件”切换；提问和审批仍直接出现在消息流，不能藏在角标内。侧栏宽度的用户调整可留后续，不是首版必须实现。

设计复核：不使用通用首页大数字、渐变宣传块或等尺寸功能卡；将空间用于任务正文和可追溯证据。Element Plus 保持熟悉的管理操作，独特性集中在任务台的信息顺序，避免为视觉差异扩大组件维护成本。

## 4. 登录、账户与对话管理

登录页仅保留产品名称、账号、密码、显示密码、登录按钮和错误区域；建议管理员建号，首版无公开注册入口。账号停用、凭据错误采用不泄露账号存在性的说明；请求频繁提示稍后重试。提交期间禁用重复操作，密码不进入 URL、日志和前端持久存储。登录失效后保留不含秘密的本地输入草稿，重新登录后重新校验访问权限，不自动发送。

账户页显示用户名、角色、账号状态、个人容量、运行额度与限制来源；额度未知显示“暂不可用”，不当作零。建议支持修改本人密码，管理员重置流程不展示原密码。退出撤销当前会话，清理敏感内存缓存；不同用户登录不能复用上一用户的对话缓存。

对话列表展示标题、更新时间、最近运行状态和待处理标识。搜索只搜索本人可见对象；空态为“还没有对话，创建后即可提出任务”。标题可重命名；删除前说明会立即撤销消息和文件访问，物理删除依保留策略处理。非终态运行存在时，建议先取消并等待状态确认再删除，避免用删列表项掩盖仍在运行的任务。删除失败保留原条目与错误，不先假装成功。

新建对话为空白任务区，显示简短示例提示但不自动填入业务要求。输入支持多行、粘贴和附件，Enter 发送、Shift+Enter 换行；输入法组词期间 Enter 不发送。发送以服务端接收为准，网络超时可查询同一请求结果，不以重复点击再创建 Run。

## 5. 提交任务、能力选择与执行中输入

提交区依次提供任务正文、已选附件、Skill 范围、代码修复设置及“发送任务”。正文不能为空；允许纯文件任务时仍需用户说明目的，不能替用户猜目标。上传未完成、文件校验失败或选用能力失效时阻止提交并定位问题。

图片／文档上传与解析分开。文件完成安全校验但仍在解析时，用户可选择“等待解析后发送”，或在页面明确提示后选择“提交并等待文件就绪”；后一方式把附件解析列为 Run 的显式依赖，在依赖可用前不让模型基于空内容执行，不额外占用活动执行槽位。尚在传输或安全校验、已失败或已撤销访问的附件不能作为已可用输入。解析失败后由用户移除、替换或按真实可用范围继续，不自动假设模型已读懂。两种提交方式都服从当前对话锁与 unknown 阻塞，不能借文件解析另开并发任务。

Skill 范围默认“自动选择可用 Skill”；点击展开公共／个人分组及搜索，用户可选择“限定范围”并勾选多个版本对应的 Skill。限定为空时显示“本轮不使用 Skill”，不得回退自动模式。运行采用服务端固定版本快照，页面显示“提交时版本”；后续更新不会悄悄改变本轮。缺少适配能力时可以提问或说明限制，不强行选 Skill。

修复设置显示“代码失败后自动修复：继承管理员设置／开启／关闭”，管理员可禁止用户覆盖；同时显示允许次数及来源，不让用户输入超出配额的数字。关闭不影响错误记录、产物检查和清理。

一个对话最多一个非终态 Run，等待也占对话运行锁。运行时可继续编辑草稿和上传待用文件，但“发送任务”禁用并说明当前阻塞原因；普通消息不自动排队、不静默产生并发 Run。需要补充当前任务时使用当前问题组的回答入口；改变任务目标可取消后重新提交，但必须先确认不存在未核对的外部写操作。即使 Run 已终态，只要存在 unknown 外部写，主输入仍禁用新任务并显示“请先核对外部操作”。若未来增加执行中指令，应单独设计协议，首版不把普通文本当成实时中断控制。

## 6. 状态呈现、过程与取消

| Run 状态 | 中文显示 | 主要可用操作 |
|---|---|---|
| queued | 排队中 | 查看排队提示、取消 |
| preparing | 准备中 | 查看准备步骤、取消 |
| running | 执行中 | 查看进度、输出、取消 |
| validating | 检查结果 | 查看检查项、取消 |
| waiting_user | 等待回答 | 回答专属问题、取消 |
| waiting_approval | 等待批准 | 批准／拒绝具体操作、取消 |
| resuming | 恢复中 | 查看文件恢复说明、取消 |
| cancelling | 正在取消 | 查看已确认范围；不重复取消 |
| succeeded | 已完成 | 查看结果、下载、继续对话 |
| failed | 执行失败 | 查看原因；无 unknown 阻塞时可新建一轮 |
| cancelled | 已取消 | 查看保留成果和外部操作说明 |
| interrupted | 执行中断 | 查看未知动作与恢复限制 |
| expired | 已过期 | 查看原因；无 unknown 阻塞时可重新提出任务 |

waiting_user／waiting_approval 释放全局执行槽，但不释放对话锁。答复受理后进入 resuming，仍需等待调度槽位；显示“已收到回答，等待恢复”，不得承诺立即执行。以上最后六类中 succeeded、failed、cancelled、interrupted、expired 为终态，cancelling 仍是非终态。服务端返回权威状态，前端不凭超时自行改成失败或中断。

清理单独显示 `not_created / active / cleanup_pending / cleaned / cleanup_failed / cleanup_unverified`，中文为“未创建环境／环境使用中／等待清理／已清理／清理失败／清理待核实”。已完成且清理失败时，结果仍可查看，另显红色提示和处理记录；不把整个任务伪装为全绿。等待方案统一为立即保存工作文件快照并清理环境，回答后新建环境恢复文件，不保留等待中的进程和内存。页面显示实际快照和清理结果，不能在清理未确认时提前写“已清理”；TTL 和等待截止时间均使用服务端实际值，未知不编造倒计时。

执行过程按时间列准备、Skill 读取、MCP 调用、代码执行、修复、校验和清理。默认摘要，展开可见脱敏参数、耗时、stdout／stderr、真实退出码和输出截断标识。工具步骤不是模型思维链。输出区按需加载，超大日志仅显示已保存片段和可获准下载入口；“输出已截断”必须持续可见。

取消按钮打开轻量确认，说明停止后续操作，已完成的外部修改不能保证撤销。确认后立即显示“正在取消”，直到服务端确认；远程动作状态未知时展示具体调用和“结果待核实”，不写“已撤销”。失败页不提供“从失败步骤无条件重试”按钮；只有无 unknown 阻塞时才提供“基于当前结果继续”，创建明确的新一轮并显示不会恢复内存或进程。

对 interrupted／expired／failed／cancelled 等任何终态，存在 unknown 外部写时均使用“核对外部操作”专用流程，不能继续发送新 Run。核对页显示待核对调用、脱敏目标与参数、时间、远端请求标识和现有证据；仅所属用户可登记经审核的远端证据，服务端审核证据与调用归属、目标和结果一致后更新核对状态。普通聊天、模型自述、管理员直接放行或“忽略继续”都不能绕过 unknown。核对不重放原工具、不恢复终态 Run；全部 unknown 已有可信结论后，服务端才可解除新 Run 阻塞。无充分证据则保留未知与阻塞并提示补充证据。

## 7. Question Human 与操作审批

### 7.1 普通问题

Question 的 question_id 代表一个问题组，每组最多 3 题。一张问题表单展示组内全部提问、必要背景、单选／多选／文本输入、可选补充文件、统一截止时间和“提交整组回答”。必填项有文字标记，多选明确最少／最多选择数；所有必填题通过校验后才一次提交整组答案、一次触发恢复，不逐题 resume。答案按题目 ID 组织并绑定当前 question_id，不能误投到另一问题组。补充文件属于本对话、关联当前整组回答，上传成功后才可提交。

提交期间禁用按钮；成功后保留答案快照和时间，显示“已回答，等待恢复”。刷新或跨设备仍显示持久化问题。重复提交返回原结果；其他页面已答则刷新为只读。已取消、过期、结束的问题显示原因，不再接受迟到答案。普通聊天中的“好的”不代替结构化回答。

### 7.2 具体操作审批

审批卡标题采用“请求批准外部操作”，突出连接、工具、目标系统／对象、动作、实际参数摘要、涉及文件、潜在影响和有效期。提供可展开的脱敏完整参数，不展示密钥；参数被遮蔽但影响无法理解时不能诱导批准。按钮为“批准此操作”和“拒绝”，拒绝可附原因，不使用含混的“继续”。

批准绑定审批 ID、工具调用参数指纹与权限版本；审批参数改变或过期需重新展示。用户普通答复、Skill 文本或模型声称“用户已同意”均不能批准。拒绝后显示已拒绝，Agent 可在原授权范围内寻找方案、提问或结束，不能换名字执行相同副作用。批准不等于远程写入已完成，完成结果仍由工具调用记录证明。

同一等待在消息流和任务台引用同一记录；点击任务台“去回答／去审批”定位卡片，不复制两份可独立提交的表单。问题组内最多 3 题须整组提交，不允许一题答复解锁整组。浏览器关闭不等于拒绝，未回答也不等于同意。审批到期 10 分钟时记录 denied 并恢复当前 Run，让 Agent 选择获准替代方案或结束，不将其直接显示为 Run 过期；普通问题等待 24 小时或 Run 总 TTL 48 小时到期才按规则落为 expired。终态仍受 unknown 外部写核对阻塞约束。

## 8. Todo、文件、产物与历史

Todo 显示待处理、进行中、等待用户、已完成、已跳过、已取消，支持查看调整原因和关联步骤／产物。用户通过对话要求调整，不直接勾选系统执行完成。任务台展示本轮计划；历史轮次可展开，继承事项标明来源。没有 Todo 时显示“此任务未建立计划”，不强制制造空步骤。“全部完成”仍不能覆盖 Run 失败、产物无效或环境未清理。

文件区分“上传输入／保存的工作文件／发布产物”，列表显示名称、用途、版本、大小、来源轮次、上传或生成时间、可用状态。添加同名文件生成新引用，以时间或版本区分，不覆盖历史；模型和下一轮选用文件依据 ID。上传过程可逐项取消、重试，失败明确大小、类型、容量或网络原因；前端校验只是提前提示，服务端仍校验内容与归属。

输入附件进一步标记 `image`／`document` 类型（其他允许格式按后端分类），分别展示缩略图或文档图标、页数（可得时）、解析摘要与处理范围。状态包括“上传中／安全校验／解析中／可用／部分成功／失败”，不能用上传进度100%表示内容已理解。ready／可用表示经过安全处理的文字或页图索引已可读取；“需视觉理解”是needs_vision页面标志，不阻塞Run准入。扫描页渲染和索引就绪即可进入Run，真正模型识别在Run内按需进行；是否被模型实际看过另记录，避免先识别才能运行、先运行才能识别的死锁。页数未知显示“正在识别页数”，不显示零页。

部分成功必须列出已解析／待识别／失败页和原因，提供重试适用页、查看原文件及调整任务范围入口；关键页不可用时不静默按完整文档推断。解析摘要是快速核对信息，例如“共 12 页，已提取 10 页文字，2 页待视觉识别”，不是对整份文档的正确性保证。缩略图和页图预览使用鉴权资源，不泄露存储路径，不执行文档活动内容。

Agent 回答中的来源引用建议显示“文件名 · 版本 · 第 N 页”，点击打开对应原文或页图；文本切片可附段落定位，表格与图表尽可能保留页和区域来源。原始 `file_refs` 持续保存且可重新读取，不能只留下解析摘要而丢失原文入口；重新读取仍逐次检查用户、对话归属及保留状态。若原文件已删除或不可访问，引用显示相应原因，不用缓存摘要假装已再次核验。

提交前的附件是待引用文件；删除草稿附件移除本次引用，不误删已经被历史运行使用的文件。文件存储成功但提交失败时，可在本对话重新选择，孤立文件由服务端保留策略处理。界面不提供任意宿主路径输入，不显示真实磁盘路径。

产物展示校验状态及范围，例如“文件存在、格式可读取；未核验所有业务内容”。缺少必需产物时列为失败证据，纯文字任务显示“本轮无文件产物”即可。下载通过鉴权接口，不生成永久公开链接；删除对话或撤销权限后下载失效。预览仅允许受控文本、图片和明确支持的类型，不直接执行不可信 HTML、脚本或嵌入页面；其他类型提供下载。预览失败不等于文件不存在，分别显示原因。

历史消息分页向上加载，恢复滚动位置；用户手动向上阅读时不强拉到底部，用“有新进度”提示。每轮保留输入、能力版本、问题／审批答复、过程和结果。下一轮顶部可显示“将恢复 3 个相关文件”，支持查看明确引用；不承诺恢复 Python 变量、进程或依赖。摘要是上下文派生信息，不能替代原始证据。

消息区提供可折叠的 `context_status`，默认仅显示“上下文已整理，引用原文可查看”；展开显示整理时间、覆盖消息范围、保留的文件引用和仍可回读的来源，不展示模型内部推理或完整敏感上下文。整理中、失败或部分整理分别显示实际状态，不因压缩失败删除历史。summary是派生整理视图，不是原文、执行事实或新增授权的权威来源；出现歧义、细节缺失或证据冲突时回读原消息与文件。用户确认的约束和原始引用不能被摘要文字悄悄覆盖。

## 9. Skill 与 MCP 管理

文件恢复说明补充：纯文本或只读任务没有修改工作区时沿用之前有效工作快照，不用空记录覆盖它。界面显示实际来源Run与时间；本轮快照保存失败或不完整时不能显示“全部工作已恢复”。

### 9.1 Skill 库

列表字段：名称、简介、公共／个人、当前版本、状态、更新时间。筛选公共／个人／可用／停用，支持搜索。空态提供“上传个人 Skill”，无公共能力时仍允许通用对话。详情展示 SKILL.md 的安全渲染、资源树、版本记录、静态校验摘要和可用范围，不执行说明中的命令。

个人上传建议 ZIP：先选包、上传、静态校验，成功后确认名称与简介，保存新版本；失败展示入口缺失、路径非法、文件冲突、容量等具体问题。提示“校验通过仅表示包结构符合要求，不代表代码安全”。更新生成版本，不改历史快照。删除／停用说明对新运行和历史引用的影响；公共 Skill 对普通用户只读。运行中工作副本修改显示差异，不提供自动覆盖源版本按钮。

管理员公共 Skill 页面增加发布／停用、版本切换、变更说明与发布记录；发布前显示包校验状态，不把上传成功等同于发布。硬性权限撤销由服务端后续调用检查，界面明确可能影响正在运行的任务。

### 9.2 MCP 连接

MVP个人远程Streamable HTTP支持无认证、静态Bearer，并因实际Skill套件评估纳入标准OAuth宿主设计。OAuth入口只有实际AuthProvider已配置时才可用，未实现／未核验显示能力受阻，不假装已登录。个人连接不能填本地启动命令。stdio 仅管理员批准部署，普通用户只能使用获授权连接。

列表显示连接名、个人／共享、传输、脱敏地址、启用状态、最近测试时间、工具数量及凭据是否已配置。新增表单为名称、URL、认证方式、Bearer 密钥输入、说明；秘密提交后不回显，编辑时显示“已配置”，仅主动替换才发送新值。地址受服务端策略限制，测试不能成为访问任意内网的代理。

“保存连接”和“测试连接”分开：保存不表示连接成功；测试说明将发起握手和工具发现，不执行有业务副作用的工具。详情显示发现的命名空间工具、简介、是否获准及审批策略。连接可处于未测试、测试中、可用、认证失败、不可达、协议不兼容、停用；错误保留脱敏诊断与处理建议。已发现工具列表标明时间，不能把缓存当成当前在线保证。

停用阻止后续调用；断开并删除凭据前说明历史记录保留且已发生操作不会撤销。共享连接只向普通用户展示授权工具和是否可用，不暴露共享密钥。管理员设置共享账号用途、授权用户及工具范围，默认不能让公共 Skill 自动借用个人账号。缺少连接时从问题卡跳转管理页，返回后仍需服务端确认权限，不能由前端直接跳过等待。

## 10. 管理员页面

用户管理表显示用户名、角色、状态、创建时间、容量、额度与活动运行数；操作为创建账号、启停、调整额度、重置密码。创建表单说明账号交付方式，避免在审计里记录临时密码。停用提示登录撤销、后续调用和活动任务的处理策略，执行后显示实际受影响数量；不擅自推断所有外部调用已终止。管理员默认无任意打开他人对话或下载文件入口，跨用户内容访问需后续明确授权设计。

运行管理按状态、用户和时间筛选，显示 Run 标识、归属、阶段、耗时、错误类别、Sandbox 标识及清理状态。默认是运行元数据和脱敏诊断，不是用户完整正文。清理异常可查看重试清理记录；只允许针对受管实例的业务操作，不提供任意 Windows 命令执行框。清理重试独立于任务重跑，避免误触外部业务。

运行配置分组如下：

| 分组 | 字段及交互要求 |
|---|---|
| 模型 | 服务地址、兼容协议、模型名、密钥已配置状态、参数；测试不创建业务任务 |
| 调度与预算 | 全局／用户并发、队列上限、步数、运行与单次调用时限、模型用量上限 |
| 修复 | 默认开关、允许覆盖、最大次数、适用错误类型 |
| 文件与等待 | 上传／产物限制、个人容量、等待期限、即时快照清理与 TTL |
| 访问与审批 | 模型／MCP／Sandbox 三类网络策略、工具操作分类、审批有效期 |
| 数据保留 | 消息、文件、输出及审计保留规则；逻辑删除与物理清理区别 |

配置页显示当前版本、修改前后差异、生效范围和保存结果。数值不擅自沿用临时验证参数。提交失败保留草稿；并发修改用版本冲突提示，不静默覆盖。大部分预算建议对新 Run 生效，权限撤销按实时规则生效，具体规则由后端契约明确。配置保存不等于网络／资源策略已真实强制，未验证项显示“未验收”，不可展示为安全保障通过。

供评审的初始建议值统一为：全局活动执行 2、每用户 1；全局排队上限 100、每用户排队上限 10；单文件 20 MiB、用户容量 1 GiB、每 Run 输入合计 100 MiB；执行预算 15 分钟（不含等待）；普通问题等待 24 小时、审批有效期 10 分钟。这些是 D 值，不是已确认容量或性能保证。页面从服务端配置读取，不把数字写死在组件；等待不占活动执行名额，但对话锁仍生效。

总 Run TTL 48 小时、queued 等待上限 1 小时、快照合计 100 MiB／最多 1000 文件亦为 D 值，细节以技术设计统一约束为准。页面区分执行预算、等待期限和总 TTL，不把三个计时器混成一个剩余时间。

## 11. 前端状态、API 契约与可访问性

### 11.1 Vue 组织方式与字段约束（D）

页面建议按对话、运行详情、Skill、MCP、账户、管理划分；组件只承担呈现与交互。对话工作台拆为消息流、输入区、问题组表单、审批卡、Todo、文件区和环境清理摘要，避免将请求、权限推断及全部事件处理堆在一个 `.vue` 文件。Composition API 的 composable 负责明确的交互复用，例如运行事件订阅和上传状态；不为少量页面引入泛化插件框架。

Vue Router 4 管理页面及对象 ID，路由守卫负责提前提示登录和角色限制，服务端仍逐次鉴权。TanStack Vue Query 管理服务端查询缓存、加载与错误、提交后失效；查询键含当前身份和对象 ID，退出或切换用户清空旧身份缓存。原生 fetch 封装仅统一会话、错误与取消请求。SSE 适配将事件合并进对应对象缓存或触发重新获取快照，不再维护第二套彼此竞争的运行状态。

表单草稿、抽屉开关和焦点属于本地 `ref`／`reactive` 状态。首版可不引入 Pinia；若后续确需 Pinia，仅存放跨页面 UI 偏好等少量状态，不复制 Run／Question／Approval 服务端事实，不把待回答是否完成记成浏览器独有开关。服务端返回的可用操作决定按钮状态；unknown 阻塞优先于终态外观。

前端手写 JavaScript 和 `.vue` 的 `<script setup>`，不使用类型扩展语法。核心 DTO（RunSnapshot、QuestionGroup、Approval、FileRecord、ApiError、RunEvent 等）用 JSDoc 的 `@typedef`／`@property`／`@param`／`@returns` 标注字段、可空性和用途；这提供编辑提示与静态分析依据，不等同运行时验证。以经评审的后端 OpenAPI schema 为契约，API 边界验证字段和事件 payload；缺少必需字段、未知枚举或格式不符时停止相关提交并提示刷新／版本不兼容，不凭空补出成功状态。验证器只保留必要错误摘要，不记录密钥或敏感正文。

MongoDB 文档模型及内部索引由后端设计管理，API DTO 不直接暴露数据库记录、查询表达式或原始内部对象。浏览器提交文件 ID、对象 ID、revision 与幂等键，不提交数据库查询条件，也不依赖数据库会话或 MongoDB SDK。此边界便于将页面与业务迁入已有系统。

前端逻辑同样遵守项目 15% 中文注释率目标，`.vue` 的手写状态、事件、请求、权限及恢复逻辑纳入代表性统计；纯 DOM／模板标签豁免。JSDoc 中有实际说明作用的中文文档可依项目口径计为注释，不用重复字段翻译凑比例；第一次实施统一混合文件统计工具与排除项。本次仅设计文档，不声称注释率已达标。

### 11.2 服务端契约与页面状态

服务端至少提供以下稳定契约；具体 URL 在 API 设计中统一，不在本文重复造一套业务协议：

- 对话与运行快照包含对象 ID、归属校验后的可用操作、状态、revision、服务端时间、当前等待项、清理状态及 unknown 写操作阻塞原因。终态不代表 can_create_run=true。客户端不提交可信 user_id，不以本地缓存判断权限。
- 创建 Run、回答、审批、取消使用幂等键；变更携带期望 revision。重复请求返回同一结果，冲突返回最新状态与原因，不要求用户猜是否执行成功。
- SSE 事件包含 event_id、run_id、单调序号、事件类型、时间及有类型的 payload。先取得快照，再补读游标后事件，去重并处理断线；缺口或游标过期重新取快照。SSE 断线只显示“连接中断，正在恢复进度”，不改变 Run 状态。
- 问题组返回 question_id、最多 3 个带题目 ID 的题、类型、选项、必填约束、统一有效期和可提交状态，整组一次提交。审批独立返回参数指纹和期限，到期 denied 恢复。回答受理与恢复执行分别通知，不能把 HTTP 200 画成任务完成。外部操作核对提供本人证据登记和审核结果读取契约，不提供忽略 unknown 的放行接口。
- 文件接口返回 file_id、版本、用途、大小、内容类型、image／document 分类、安全校验与解析状态、页数、解析摘要、部分失败范围、页／区域来源引用及可下载能力；原始 file_refs 支持重新读取。上传完成事件与解析可用事件分开，Run 快照明确文件依赖及阻塞原因。下载逐次授权，前端不接收存储绝对路径或原始凭据。
- context_status 返回整理状态、覆盖范围、时间与可访问原文引用，summary 与源消息／源文件关联；前端只展示可公开的整理说明，不能因摘要“权威”就把它当作原文、审批结果或用户新决定。
- 错误包含稳定 code、可读 message、request_id、字段错误、是否可重试和必要的当前状态；401 处理登录失效，403／404 防止对象泄露，409 处理锁或版本冲突，413／配额错误定位容量，429 显示稍后重试，服务端故障保留诊断标识。

页面状态分为首次加载、局部加载、空数据、成功、可重试错误、无权访问；不能所有情况都显示空列表。保存草稿与服务端运行事实分离，刷新后以服务端快照恢复，待回答和审批不靠浏览器内存保留。切换对话取消旧查询或按对象 ID 丢弃迟到响应，避免把 A 对话结果渲染到 B。

所有操作可用键盘完成；对话、消息、任务台使用清楚的地标和标题层级。弹窗／抽屉打开后管理焦点，关闭回到触发点；必填和错误与输入关联。状态更新用克制的 live region 通报关键变化，不逐 token 朗读。主按钮和危险按钮文字明确；图标按钮有可读名称。支持 200% 缩放、系统减少动画偏好，表格小屏改字段堆叠或横向滚动，不截断唯一辨识字段。

### 11.3 前端验证建议（D）

使用 Vitest 与 Vue Test Utils 验证问题组整组必填、提交幂等交互、unknown 时主输入阻塞、身份切换缓存清理、断线补读与迟到响应丢弃；测试真实状态边界，不逐项镜像组件实现。使用 Playwright 验证浏览器中的登录与隔离、上传下载、问答／审批、取消、失联恢复、响应式与键盘路径。模拟测试和真实后端／MCP／Sandbox 集成分别记录，组件测试通过不能代替多用户验收。本文和静态预览不安装或运行这些依赖。

2. **运行中保留草稿但不接受普通消息作为新任务。** 简化同对话串行和恢复语义；如果需要实时改指令，应追加独立设计而不是暗中排队。
3. **个人 MCP 保留配置能力，首版限远程 Streamable HTTP 与静态认证。** 标准OAuth纳入通用宿主能力设计并逐服务验收；任意个人stdio启动仍不允许，不隐藏认证与主机执行复杂性。
4. **审批和普通问题独立，结果和清理独立。** 页面略多一层状态，却能避免把回答当授权、把成功当已清理；这是必要的可解释性成本。
5. **沿用 Element Plus，定制工作台结构和少量 tokens。** 优先可读、可迁移与交互一致性，不投入营销首页或完整自研组件库。

实施验收应覆盖键盘提交和中文输入法、上传失败及同名版本、断线补读、双页面重复回答、迟到审批、运行锁冲突、权限撤销、终态与清理失败并存、未知外部副作用、移动端待处理入口以及跨用户缓存／下载隔离。本文仅完成文档设计审查，未运行前端测试、服务集成或多用户验收。

## 13. 实际Skill评估后的通用页面补充

依据[通用宿主补充设计](AgentDock-通用Skill宿主能力设计-v1.1.md)，不添加CAD专用页面：Skill上传支持Bundle入口／成员／获准依赖范围和RuntimeProfile匹配结果；连接页展示正式OAuth登录、取消、刷新失败和撤销，授权以服务端回调为准。工作台增加外部目标／会话／证据区，区分用户已打开与Agent已观察，截图需实际视觉输入；不保证外站可嵌iframe。

用户可在明确资源、动作、参数范围及额度后授予TaskScopedGrant，越界或危险操作仍审批；普通问题不能授予范围。新增个人资料集合的候选／发布／冲突界面，正式保存授权独立于效果认可。显示领域状态文件及来源，不把Todo完成替代领域验收。静态HTML仅示意原三页，尚未画出全部新增配置表单，实际UI按此设计继续细化。

附件还区分“文件已保存”和“内置解析器可解释”；已批准的其他格式可显示“由Skill／工具解析”，例如样本STEP由几何工具生成数据和图片后交模型，不因内置PDF／图片解析器不支持就禁用全部任务，也不把文件名当成已理解内容。

未知外部写的屏障还可能来自本账号其他对话或共享连接，受影响工具显示“需先核对既有操作”，不显示其他用户私有细节；新对话不能绕过。跨对话资料只通过明确获准AssetCollection或重新上传使用，不提供未完成Run的一键跨对话恢复。
