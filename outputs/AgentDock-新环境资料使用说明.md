# AgentDock 新环境资料使用说明

日期：2026-10-29。本文帮助在其他环境阅读资料和接续研发，不声称产品已实现或服务已部署。

## 1. Git仓库包含什么

- AGENTS.md、Git忽略／换行规则、README入口。
- 完整与简版需求、现行及历史技术设计、UI和执行等专题。
- 逐节点计划、交付报告模板、暂停回退与会话接续记录。
- Skill静态适配报告及文件hash清单；**不包含用户外部Skill原始套件**。
- 静态UI／架构HTML预览、图源、截图与生成检查证据。
- 历史OpenSandbox SDK验证的输入、结果和报告，包含失败尝试及清理事实。

## 2. 不会随克隆获得什么

`.env`、管理密钥、模型Key、MCP令牌、OAuth会话、work中的虚拟环境和临时脚本、回退文件、运行数据都未纳管。已有服务、Docker镜像和Python工具安装也不会随Git复制。

这些项目需要在新环境按对应节点说明准备。当前尚无产品.env.example或可运行后端／前端，不编造启动步骤；后续研发节点实际交付时再补。

## 3. 路径怎么理解

| 资料中的路径 | 含义与新环境处理 |
|---|---|
| 仓库内相对链接 | 随克隆保留，优先从README和文档导航进入 |
| D:/Projects/AgentDock | 当前Windows工程位置；历史说明不是把这个路径写死到未来业务代码 |
| D:/Work/skills及行号链接 | 用户提供的外部评估样本；新环境需用户另外提供同版本资料或指定新位置，不能自动下载替代或执行 |
| work/verify_opensandbox.py等 | 原电脑临时验证资产，刻意不提交；报告可阅读，但原临时脚本不可从本仓库复现，后续节点重新交付受控验证入口 |
| 架构检查JSON中的本机路径 | 当时工具的输入／输出证据，保留原样以免破坏hash和历史事实，不作为产品配置 |

Skill行号引用和hash基于当时样本版本；用户更换套件后需重新核对。仓库不复制第三方／用户Skill源码，也不假定外部路径存在或获执行授权。

## 4. 正确接续顺序

先读AGENTS、会话接续说明末尾最新记录、导航、v1.2逐节点计划及本次节点专题。不要采用旧v1.0技术稿里的React／TypeScript／PostgreSQL建议，不要把历史“未配置Git”记录当最新状态。

截至本次资料纳管，Git身份及origin已配置，初始规则提交已推送。产品研发仍暂停；具体节点开工另需明确指令，不能因克隆仓库或读取提示词自行安装、恢复回退目录或写产品代码。

## 5. 证据和可复现边界

静态HTML可用浏览器打开，GitHub可能显示HTML源文件而非直接运行。架构及UI截图是当时设计检查结果；不代表真实服务联调。生成JSON可能含工具安装目录和旧输出路径，不要求新环境装同一工具才能阅读文档。

SDK成功报告只覆盖其中记录的版本、镜像、直连及小文件执行场景；失败报告仍保留。没有真实模型、MCP、多用户产品或Mongo检查点测试通过记录。不能把资料齐备等同部署完成。

## 6. 本次提交检查

资料纳管前对文档、JSON和HTML执行已配置密钥值匹配及常见凭据格式扫描，检查本地链接和JSON可解析性；未发现匹配仅说明所做检查通过，不保证不存在所有敏感信息。截图为既有静态设计预览，未新增真实用户界面截屏。

现行资料及历史证据按主题分批首次提交；不把work、.env、缓存、回退副本或真实用户输入一起打包。后续用户可以从Git历史逐次查看各主题。

## 7. Git连接与本机代理

当前电脑的GitHub连接已配置为使用已有系统代理，配置仅在本地`.git/config`，不随克隆传播。其他环境无需照抄代理地址，应使用其自身网络。历史TLS错误、实际排查证据、处理和限制见[Git连接处理记录](AgentDock-Git连接排查与处理记录-20261029.md)。
