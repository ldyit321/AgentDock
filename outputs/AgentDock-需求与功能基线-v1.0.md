## 2. 项目由来与定位

### 2.1 起点

用户已有运行健康的 OpenSandbox Server，希望在 Windows 上创建 LangGraph 项目，验证实际 Skill 脚本工作流：解析目录、上传脚本和输入、准备依赖、执行 Python／CLI、获取输出和退出码、失败修复、下载产物及 finally 清理。

用户不希望把工程代码放在 Ubuntu 中编辑，要求工程位于 Windows D 盘。早期“外部电脑能访问”已澄清为当前 Windows 宿主机能够访问 WSL2 中的服务；没有因此确认公网部署、跨地域访问或其他电脑远程接入。

### 2.2 演进后的目标（U）

项目已经扩大为一个多用户的通用 Agent 网页 MVP。Skill 是可扩展能力来源之一；MCP 是外部工具连接方式；OpenSandbox 是代码执行环境；LangGraph 组织 Agent 流程。

它不绑定 CSV、Excel、报表或任何单一业务。业务样例仅用于验收，不能反向限定产品范围。

### 2.3 命名（U）

当前名称为 **AgentDock**，项目路径 `D:\Projects\AgentDock`。

曾提出并放弃的名称包括 `skill-agent-mvp` 和 `SkillHarbor`。不要继续沿用旧名称建立目录、写 README 或命名配置。

## 5. 目标、非目标及失败判据

### 5.1 MVP 目标

- 多个用户通过网页使用同一套 Agent 服务，数据和权限隔离。
- LLM 按需发现、读取并使用通用 Skill，而非仅执行写死入口。
- 处理真实文件、运行代码、读取结果，并支持有限失败修复。
- 根据当前用户连接调用 MCP，支持外部数据与 Sandbox 文件之间的受控传递。
- 同一对话持续交流，能追加文件、沿用前序成果。
- 可通过 Question Human 补充信息，通过 Todo 展示计划及进度。
- 所有重要执行动作有记录、预算、取消和清理机制。

### 5.2 暂不纳入的建议范围（D）

- 公网发布、企业 SSO、组织与复杂角色体系、计费系统。
- 多 Agent 编排、自主常驻后台任务、跨主机分布式调度。
- 任意模型无适配即兼容、任意 Skill 无依赖限制即运行。
- 自动执行上传内容提供的 Windows 安装命令或 MCP 启动命令。
- 自动跨对话学习用户资料、向量检索知识库。
- 无条件恢复 Python 内存、后台进程及整个 Sandbox 镜像。
- 外部操作的自动回滚、任意中断节点的无风险自动重放。

### 5.3 不能接受的结果

- 只有 hello-world，无真实文件、错误和产物链路。
- 把固定脚本运行包装为已经实现 Skill 理解。
- 公共 Skill 暗中使用管理员的个人凭据。
- 任务删除或取消后，下载链接仍能越权读取文件。
- 模型说完成就直接成功，不检查执行证据。
- 只靠提示词限制权限或网络。
- 一直重复询问已经讨论过的问题，或在需求阶段未经授权继续开发。

## 6. 部署边界与组件职责

### 6.1 逻辑结构

```text
浏览器（用户／管理员）
        |
        v
Windows：AgentDock 应用服务
  身份与权限 / 网页 API / 文件访问 / 任务调度
        |
        +-- LangGraph + AI Harness
        |     模型适配 / 上下文 / Skill 发现 / Todo / Question Human
        |     工具执行 / 预算 / 事件 / 取消 / 确认
        |
        +-- MCP 客户端与按用户授权
        |     已批准的本地 MCP / 个人与共享远程 MCP
        |
        +-- 数据库 + D 盘文件存储 + 凭据保护
        |
        +-- OpenSandbox SDK
                 |
                 v
       WSL2 / Docker Desktop：OpenSandbox Server
                 |
                 v
       每轮／每次运行专属 Sandbox
       Skill 工作副本、输入、代码、依赖、产物
```

这只是逻辑职责图，不表示已决定使用独立微服务。

### 6.2 Windows 端

存放工程、应用配置、数据库或数据库连接配置、上传文件、Skill 库、执行记录和产物。可以用主机程序运行应用自身逻辑，但不得把不可信 Skill 作为 Windows 代码执行。

### 6.3 Sandbox 端

运行 Skill 脚本、模型生成的代码和允许的 CLI，准备依赖，处理本轮工作文件。默认不获取管理密钥、主机环境变量或业务 MCP 长期凭据。

### 6.4 MCP 端

提供外部系统能力。其权限和副作用不因代码在 Sandbox 中运行而被隔离；必须独立鉴权、审批和审计。

## 7. 领域对象与术语

| 对象 | 含义 |
|---|---|
| 用户 User | 身份、角色、权限及配额的主体 |
| 对话 Conversation | 多轮消息、文件和工作成果的容器 |
| 消息 Message | 用户输入、Agent 回答、问题和答复等内容 |
| 运行 Run | 某次用户输入触发的完整处理过程，可等待回答后继续 |
| 步骤 Step／工具调用 | Run 内一次具体执行，有参数、状态和结果 |
| Sandbox | 一次 Run 的临时代码运行实例；恢复时可能更换实例 |
| Skill | 名称、简介和资源组成的能力包 |
| SkillVersion | 某一固定的不可变 Skill 内容版本 |
| 工作副本 | 当前对话／Run 使用和修改的脚本及文件 |
| MCPConnection | 特定所有者、认证和工具策略的连接配置 |
| Question | Agent 请求用户补充信息的持久化交互 |
| Approval | 绑定具体外部操作的批准／拒绝记录 |
| Todo | 可变任务计划，不能充当执行成功证据 |
| Artifact | 被校验并发布给用户下载的产物 |
| Event | 展示和诊断用结构化运行事件 |

“任务”在早期交流中有时指对话，有时指 Run。后续 API 和数据设计统一采用上述划分。每轮“独立 Sandbox”按 Run 理解；同一 Run 等待用户后可以创建替代实例，不要求保持同一实例 ID。

多用户隔离为 U；下列具体权限划分为 D。

| 能力 | 普通用户 | 管理员 |
|---|---|---|
| 登录与退出 | 本人 | 本人 |
| 创建、查看、取消 Run | 本人数据 | 本人；可处理系统异常，范围需明确 |
| 查看、下载输入与产物 | 本人数据 | 默认不提供任意浏览他人正文的功能 |
| 使用公共 Skill | 已启用且获准的内容 | 同左 |
| 上传和管理私有 Skill | 本人 | 本人 |
| 发布、停用公共 Skill | 不允许 | 允许 |
| 管理个人远程 MCP | 本人，受地址与认证策略限制 | 本人 |
| 部署 stdio MCP | 不允许任意启动命令 | 管理员部署 |
| 管理共享连接与配额 | 不允许 | 允许 |

管理员在宿主机上的实际系统访问权不等于应用 UI 默认公开所有用户文件；管理员异常处理应尽量使用状态和脱敏信息。

任何查询、修改、下载、取消、事件订阅、回答问题、审批和恢复都必须服务端检查归属。客户端提供的 user_id、路径或不可猜测 ID 不构成授权。

## 9. 网页与用户操作

### 9.1 登录

支持登录、退出、登录过期反馈。D：管理员预建账号，不开放自助注册。密码保存摘要，不保存明文；登录会话与下载链接的权限检查一致。

### 9.2 对话页面

- 新建、查看及继续本人对话。
- 输入自然语言目标，上传或追加输入文件。
- 默认自动选 Skill，可限定本次允许的 Skill。
- 展示运行状态、Todo、问题、审批、操作摘要和产物。
- 支持取消运行；等待期间保留对话和已有成果。
- 页面刷新后恢复可见记录，不要求依赖浏览器内存。

### 9.3 Skill 库

查看公共 Skill 与本人私有 Skill；显示名称、简介、来源、版本和可用状态。私有 Skill 支持上传、更新和删除；公共发布由管理员负责。

### 9.4 MCP 连接页（D）

添加远程连接、选择支持的认证方式、测试、启停和断开；显示工具列表与连接状态。已有密钥不通过接口原文回传，网页仅显示已配置状态。OAuth 需要用户本人完成交互。

### 9.5 Run 详情与管理页

Run 展示起止时间、步骤、输出截断状态、错误、产物和清理状态。管理员管理账号、公共 Skill、共享 MCP、配额、排队和异常实例，不默认提供任意 Windows 命令执行入口。

## 10. Skill 发现、上传与版本管理

### 10.1 支持的内容

目标覆盖 `SKILL.md`、`scripts/`、可选 `requirements.txt`、参考资料、输入样例和其他允许的资源文件。文件名大小写兼容和嵌套目录约定为 O。

`SKILL.md` 是自然语言说明，不预设它一定包含机器可执行入口。若后来引入清单文件，应说明用途并保持与自然语言理解兼容，不能退回只支持固定入口的产品。

### 10.2 自动发现（U）

Agent 先获得用户有权限使用的 Skill 名称和简介，再按需读取完整说明与资源。用户指定范围时不能选择范围外的 Skill。模型不能列举或推断其他用户的私有内容。

D：通用任务允许选择零个 Skill，直接使用获准的 MCP 或 Sandbox 工具；没有合适 Skill 时不强行匹配。若任务缺少必要能力，应说明限制、提问或结束。是否允许零 Skill 作为建议行为等待评审，不将它冒充用户已明确决定。

### 10.3 上传与静态校验（D）

首版建议 ZIP。校验入口文件、文本可读性、路径、解压大小、数量、压缩比、重复／冲突文件名、符号链接和 Windows 特殊路径。原始文件名作为显示元数据，不直接作为宿主存储路径。

拒绝绝对路径、`..` 越界、盘符、UNC 路径和解压穿越。上传不触发依赖安装或主机执行。静态校验通过不表示脚本安全。

### 10.4 内容权限与生命周期（D）

用户上传默认私有，不自动公开；管理员发布公共版本。更新生成新版本，Run 固定版本快照。停用后禁止新选择，运行中的处理策略需明确；硬性权限撤销在下一次工具调用前检查。

### 10.5 Agent 修改

修改工作副本并保存变更记录，绝不自动覆盖公共或私有 Skill 源版本。D：后续轮次可以继承经保存的工作副本；选择恢复原版本时应明确。

## 11. AI Harness

Harness 是将模型决策转成受控执行的层，LangGraph 是其流程和状态组织方式。下列为已讨论的目标方案（D），其 Question Human 与 Todo 能力本身为 U。

### 11.1 每次运行的受控上下文

绑定服务端确认的 user_id、conversation_id、run_id、Skill 版本、MCP 授权、文件范围和预算。模型只获得必要描述，不获得管理连接客户端、原始密钥或修改身份的工具。

### 11.2 工具组

| 工具组 | 主要职责 | 强制边界 |
|---|---|---|
| Skill | 列简介、读取说明及配套文件 | 按用户及限定范围过滤 |
| 文件 | 列目录、分段读取、创建和修改 | 受控工作区与容量限制 |
| Sandbox | Python／CLI、状态和输出 | 超时、环境、执行权限及资源 |
| MCP | 外部工具调用 | 当前连接、用户权限、确认规则 |
| Todo | 建立和更新计划 | 不等同真实执行状态 |
| Question Human | 提问、等待和接收回答 | 仅所属用户可答复 |
| 产物 | 检查和发布可下载结果 | 归属、路径、类型、数量和大小 |

### 11.3 执行循环

准备上下文 → 模型选择下一步 → 参数／权限／预算检查 → 工具执行 → 记录结果 → 模型继续、等待或结束。

模型可以调整计划，不要求一次生成固定计划后机械执行。应用强制限制总时长、步数、代码及输出大小、工具调用和修复次数；识别相同失败反复出现并结束或求助。

### 11.4 结果判定

区分“代码执行成功”“任务产物满足约定”“内容质量检查”。不能把 exit=0 当成所有业务目标正确。对可机械检查的内容执行检查，对难以自动判断的内容说明验证范围，不把模型评价写成客观证明。

不是每次任务都必须运行代码或生成下载文件。纯文本答复、MCP 查询等可以无文件完成；只有任务或选定 Skill 明确要求产物时，才将缺少对应产物视为失败。

### 11.5 提示注入边界

Skill、输入文件、MCP 结果和脚本输出都可能包含指令。它们是任务数据，不能覆盖系统权限、扩大网络范围、索取密钥或授权外部写操作。权限通过工具实现约束，不能依赖提示词。

## 12. Question Human 与审批

Question Human 能力为 U；以下交互细节为 D。

### 12.1 问题类型

支持单选、多选、自由文本，以及与问题关联的文件补充。Agent 只在缺少影响任务的必要信息时提问，不为可合理决定的小事反复打断用户。

### 12.2 持久化与等待

问题包含 ID、所属 Run、提问文本、类型、选项、状态、创建时间、答复及答复时间。等待状态写数据库；页面刷新后可见。等待不持续消费模型调用或占用执行工作线程。

无答复不等于批准。重复提交回答应幂等，已取消或结束 Run 不因迟到回答重新启动。回答后恢复当前 Run 的后续步骤，不重复之前已成功的外部动作。

### 12.3 Sandbox 在等待期间

短暂等待是否保留实例、保留多久为 O。超过期限保存允许的工作文件并清理；回答后创建替代实例恢复。需要控制问答期间的存储和总等待时间。进程和内存状态无法默认恢复。

### 12.4 与操作审批分离

普通问题解决信息缺失；审批授权具体副作用。Approval 应绑定工具、连接、目标、参数摘要／指纹、有效期和当前用户。批准后参数变化须重新评估；不能把“好的”这一普通消息任意转换为批准另一操作。

对无法可靠识别是否有副作用的 MCP 工具，采用管理员明确策略或保守确认；工具自带注解不独自决定信任等级。

## 13. Todo List

Todo 机制为 U；具体状态与交互为 D。

- 复杂任务建立计划，简单任务不强制冗长清单。
- 状态建议：待处理、进行中、等待用户、已完成、已跳过、已取消。
- 支持新增、拆分、重排及说明调整原因。
- 保存变更与相关工具调用／产物引用。
- 用户可以通过对话要求调整计划，直接拖拽编辑暂不作为已确认功能。
- Todo 的“完成”是计划状态，不能覆盖 Run 错误、缺失产物或清理失败。
- 多轮对话可显示历史计划；本轮新增、继承与关闭旧事项要可区分。

## 14. 多轮对话、文件恢复与记忆

### 14.1 多轮（U）

用户可以基于已有结果继续追问、修改要求和追加文件。下一轮恢复必要输入、工作副本和产物，而不是把上次 Sandbox 永久保留。

### 14.2 三类持久状态（D）

| 类型 | 保存内容 | 用途 |
|---|---|---|
| 对话记忆 | 消息、目标、摘要、近期结果、文件引用 | 理解后续追问 |
| 执行状态 | Run／步骤／问题／审批／预算／工具结果 | 进度、恢复和排错 |
| 工作文件 | 输入、修改脚本和产物的实际字节 | 下一轮恢复与下载 |

三者不同，不能只保存聊天文本，也不能把数据库检查点当作全部文件备份。

### 14.3 上下文构建

提供系统规则、当前任务、对话摘要、近期消息、Skill 简介、按需读取的说明、文件索引和相关工具结果。完整大日志不默认进入模型；保留分页／分段读取引用。

摘要是派生数据，原消息和关键证据保留。摘要不保存密钥，归属仍按用户和对话过滤。上下文窗口与输入／输出 token 预算可配置。

### 14.4 长期记忆范围

D：第一版不自动跨对话提取长期偏好，不引入向量数据库。需要偏好时先支持用户主动填写的设置。未来增加长期记忆必须支持查看、修改、删除和明确作用范围。

### 14.5 文件选择与版本

同名文件重新上传不直接覆盖历史引用；使用文件 ID／版本记录。恢复以明确引用为依据，保证模型不会误用同名旧文件。对话删除后的文件与下载权限一起失效，实际清理及保留期限另设策略。

## 15. 模型适配与无模型诊断

### 15.1 模型无品牌绑定（U）

模型服务可配置。实现需要验证工具调用、消息格式、上下文能力、流式处理及错误行为，不承诺任意模型立即兼容。不能依赖模型必须公开内部推理。

### 15.2 模型配置（D）

管理员设置 endpoint、模型名、服务端密钥与必要参数；具体服务和兼容协议为 O。防止模型工具循环无界计费，记录可获得的调用用量。

### 15.3 无 LLM Key

保留确定性诊断流程验证 Sandbox 创建、上传、执行、下载和清理。它不提供 Skill 理解、自主规划和修复能力，也不算 Agent 验收通过。

## 16. MCP 管理与调用

Agent 服务调用 MCP、Sandbox 处理代码的职责分工为 U；管理细节为 D。

### 16.1 两类连接

- 共享 MCP：管理员配置，明确授权用户和工具范围。
- 个人 MCP：用户配置，默认只本人可用。
- 本地 stdio：由管理员批准并部署，普通用户不能上传任意启动命令在 Windows 执行。
- 远程 HTTP：建议第一版支持，准确协议版本、OAuth／静态凭据等认证支持矩阵为 O。

### 16.2 Skill 与连接分离

Skill 声明“需要某种能力”，应用匹配用户已有连接及工具。上传 Skill 不代表允许安装服务器、连接任意地址或使用管理员账号。工具名称需包含连接命名空间，避免多个连接的同名工具混淆。

缺少连接时，使用 Question Human 或连接配置入口提示用户；不要编造工具结果或默默改用他人凭据。

### 16.3 数据流

例如：MCP 查询数据 → 服务端受控保存 → 上传必要数据到当前 Sandbox → 脚本计算 → 发布产物。二进制、大结果和资源引用应有明确搬运方式、来源记录和大小限制。

反向场景：Sandbox 生成文件 → 服务端校验 → 获授权后经 MCP 提交到外部系统。不能把 Sandbox 的 `/tmp/...` 路径直接当成 Windows 或远程 MCP 可访问路径。

### 16.4 凭据与用户身份

长期凭据由服务端加密存储，不交给模型，不放入 Skill、不默认注入 Sandbox。不把 MCP 会话 ID 当成身份或授权。断开连接、令牌过期和权限撤销对后续调用生效。

### 16.5 风险与首版限制

MCP 输出可能包含恶意指令。远程地址配置需要限制 SSRF；检测内网、回环、链路本地和重定向等路径，具体实现需技术验证。管理员批准的本地 MCP 是受信部署例外，不等于普通用户可访问所有内网。

脚本内部自带 MCP 客户端调用不自动兼容 Agent 代调用架构。首版建议改为先取数据；受控代理和短期凭据属于后续扩展，未实测。

## 17. Sandbox 执行与依赖

### 17.1 生命周期

每个 Run 独立实例，明确 TTL 和资源。创建后尽早记录 ID，防止准备失败无法清理。finally 销毁与 TTL 共同兜底；finally 不能保证在断电或强制终止时运行。

### 17.2 上传和工作目录

只传递被选择的 Skill 文件、任务输入和必要恢复文件，不整体挂载 D 盘。代码、输入、工作文件、产物有清楚目录和文件索引。路径安全与宿主文件落盘隔离都需要实现。

### 17.3 执行接口

优先参数数组。当前镜像原生数组请求失败，因此需要兼容层：输入仍为结构化参数，经 Linux shell 适用的安全引用构造固定命令，或用可信启动器在 Sandbox 内 `shell=False` 执行数组。

不能直接执行模型给出的任意 shell 字符串，不能把 `sh -c`、`python -c` 当成绕过策略的通用入口。模型写 Python 文件并在 Sandbox 运行属于预期能力；它仍需受 Sandbox 的真实网络、资源和文件边界约束，AST 检查不能代替隔离。

### 17.4 依赖

依赖安装只在 Sandbox 内。`requirements.txt` 可能包含 URL、VCS、路径或构建脚本，应按策略允许或拒绝。首版支持的依赖格式、系统包、CLI 安装方式为 O；兼容性失败应可诊断，不承诺自动安装一切。

### 17.5 输出与产物

分别记录 stdout、stderr、实际退出码、执行错误和完成元数据。非零失败可能没有 complete 字段，不应误判为未收到任何结果。超时、取消和基础设施异常不能伪造为普通退出码 0。

输出应在传输／采集阶段有界，不能仅下载全部结果后截断显示。临时验证只用很小输出，没有证明流量限制已实现。

产物只能从允许路径收集，限制文件数、单文件和总大小，拒绝路径越界与符号链接逃逸；浏览器不直接执行不可信 HTML 等内容。

## 18. 网络策略

受限联网为 D，当前能力未验证。

- 可按管理员策略允许依赖源、指定公共网站和 API。
- 默认禁止代码环境接触宿主、局域网、云元数据等敏感目标。
- 网络权限不能由 Skill 或 LLM自行扩大。
- Windows 调用模型、Windows 调用 MCP、Sandbox 脚本出站是三套不同策略。
- 域名允许不等于数据不会外传，必须匹配用途和数据授权。
- 不以 DNS 名称检查或模型承诺替代实际网络强制规则。

重要：本次成功验证使用 Docker 映射端口直连，未配置或验收网络白名单、出站隔离、资源安全基线。若现有环境无法强制目标策略，应明确降级到预制依赖／断网模式，不宣称已安全支持任意上传用户。

## 19. 调度、预算、取消与重试

### 19.1 调度（D）

全局与每用户并发上限、排队、队列长度上限；建议同一对话串行。不同用户不能争用同一工作目录或实例。具体队列和执行进程模型为 O。

### 19.2 预算

配置包括模型调用／token、总执行时长、单命令时长、Agent 步数、修复次数、上传和产物容量、等待期限。数值根据宿主资源与使用目标决定，不把临时脚本 5 分钟 TTL 或 15 秒命令超时当作产品默认值。

### 19.3 取消

先记录取消请求，停止新工具调用，终止或清理本轮代码执行。对不可中断的远程请求记录状态未知，不能声称已撤销。用户晚到的回答、重复按钮和事件不能重新激活已结束运行。

### 19.4 重试与副作用

网络瞬时错误、模型错误、依赖失败、脚本失败、产物缺失分别归类。读操作可受限重试；外部写入超时可能已经成功，应查询结果或让用户处理，不盲目重放。使用远端支持的幂等机制时仍需保存调用标识。

代码修复只修改允许的工作文件；保留版本／差异和各次执行证据。基础设施错误不交给模型反复改业务代码。

原始需求中的 LLM 修复是可选能力：必须有明确的启停配置，只针对适用的代码错误，在预算内尝试；关闭时仍保存并返回完整失败信息。默认是否启用、是否允许用户对单次 Run 覆盖开关为 D／O，不强制所有任务自动修复。修复开关也不会关闭最基本的错误记录和清理。

## 20. 状态模型

以下为 D，详细状态转移需要实现设计进一步确定。

### 20.1 Run

```text
queued → preparing → running → validating → succeeded
                         |
                         +→ waiting_user → resuming → running
                         +→ waiting_approval → resuming → running
                         +→ failed
活动状态 → cancelling → cancelled
进程意外停止 → interrupted（确认中断后落为可解释的终态或等待人工处理）
```

等待状态与暂停中的图状态持久化绑定。审批拒绝后由 Agent 选择获准的替代方案、询问信息或结束，不自动绕过。

### 20.2 独立清理状态

`not_created / active / cleanup_pending / cleaned / cleanup_failed / cleanup_unverified`。运行成功和清理失败可以同时出现，UI 应同时显示；不能把“模型正常结束”当作实例已删除。

### 20.3 重启恢复

已持久化且未执行外部动作的等待问题可恢复展示。正在执行的动作可能状态不明，标记中断并核对，不简单恢复检查点后重放工具。数据库检查点、业务状态和外部副作用之间不保证天然原子性。

## 21. 持久化与逻辑数据设计

引入持久化方案为 D；具体数据库待定。

| 实体 | 关键字段／关系 |
|---|---|
| User | ID、角色、密码摘要、账号状态、配额引用 |
| Conversation | ID、owner、标题、状态、创建和更新时间 |
| Message | conversation、role、正文／引用、顺序、时间 |
| Run | owner、conversation、输入消息、状态、预算、时间、错误摘要 |
| RunSkill | run、skill_version、用途／选择来源 |
| SandboxLease | run、实例 ID、连接方式、TTL、生命周期、清理结果 |
| Skill | owner／公共标记、名称、简介、启用状态 |
| SkillVersion | skill、版本、内容摘要、存储引用、创建者 |
| FileRecord | owner、conversation／run、用途、大小、摘要、存储引用 |
| Artifact | run、文件引用、校验状态、展示和下载元数据 |
| MCPConnection | owner／共享范围、传输、地址、认证方式、密文引用、状态 |
| ToolPolicy | connection、工具标识、授权范围、审批策略 |
| ToolCall／Event | run、step、调用 ID、脱敏参数、状态、结果引用、时间 |
| Question／Answer | run、用户、类型、选项、状态、答复、幂等标识 |
| Approval | run、工具与参数指纹、决策、决策人、期限 |
| Todo／TodoChange | conversation／run、步骤、状态、顺序、变更原因及证据引用 |
| ConversationSummary | conversation、覆盖消息范围、摘要版本 |
| GraphCheckpoint | 独立命名空间及 run／conversation 关联、版本 |

这是逻辑模型，不要求一实体一表。大文件和大日志放文件存储，数据库保存索引和必要元数据。文件和数据库写入需要考虑失败后的孤儿文件清理。

### 21.1 数据库取舍

SQLite：本机部署简单，适用于有限并发，需处理写锁、事务和连接生命周期。PostgreSQL：适合多个执行进程与更高写并发，但增加部署。当前无最终选择，也没有安装或初始化数据库。

### 21.2 密钥与配置

`.env` 保存部署配置，不提交版本库、不打印、不进入模型上下文。未来 `.env.example` 只放变量名和无秘密示例。个人 MCP 凭据应加密，主密钥独立配置，不能仅靠数据库目录隐藏。

### 21.3 保留与删除

需配置文件／日志保留期限、用户容量和清理策略。删除对话后立即撤销应用访问，实际物理删除、备份保留和审计保留分别记录。Skill 被历史 Run 引用时不应悄悄破坏版本复现。

## 22. 安全要求汇总

原始明确要求与必要隔离目标：

1. 不把 Sandbox 管理密钥暴露给前端、模型或执行代码。
2. 不直接执行任意用户／模型 shell 字符串，优先结构化参数。
3. API key 使用环境变量，错误和日志脱敏。
4. Skill 和上传文件不可信；不在 Windows 执行。
5. 限制超时、代码、上传、输出和产物大小。
6. 任务、文件、检查点、MCP、问题和审批全部按用户隔离。
7. 不挂载宿主敏感目录或 Docker socket。
8. 通过服务端规则执行权限，防止 Skill 提示注入扩权。
9. 远程 MCP 地址不得成为访问内网的任意代理。
10. 依赖安装和 CLI 也是代码执行，不视为天然安全。
